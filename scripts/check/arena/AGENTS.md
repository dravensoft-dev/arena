# scripts/check/arena/

The domain for a gate that reads two or more layers at once, or the repository root.

| gate | fails when |
| --- | --- |
| `check-all.ts` | not a gate, but the runner: `GATES` is the registry, and `testStep()` is the **single authority** for how the test suite is invoked. Read the invocation there rather than reconstructing one; a narrowed run matching fewer files is indistinguishable from one matching all of them. |
| `check-docs.ts` | a `.md` exceeds its limit, 60,000 characters unless `SIZE_ALLOWANCE` raises it, a `.md` punctuates its prose with an em dash, or a hand-written source carries a comment it is not allowed: `scripts/` and tests may carry one header of at most 10 lines, everything else none. `SIZE_EXEMPT` names what is exempt from the limit by charter, `SIZE_ALLOWANCE` what holds to a higher one instead, and `PROSE_EXEMPT` the one tree exempt from the punctuation rule, each with its reason. **An allowance is not an exemption**: the document is still measured against the raised number, and one that falls back inside the shared limit fails as a **stale allowance**, as does one whose document has moved or gone. That is what keeps a raised ceiling from quietly becoming permanent. The measure is characters and never bytes, so reading a file's length by hand means `node -e "console.log(require('fs').readFileSync('X','utf8').length)"` and never `wc -m`, which reports a document of multi-byte characters hundreds over a limit it is comfortably under. Both rules read by lexing, so a `//` inside a string, a regex or a template literal is never mistaken for a comment, a `@ts-` or `eslint-` directive is a directive rather than the file's one allowance, an em dash inside a fence or a code span is the document quoting code, and a fence closes only on a run of its own character at least as long as the one that opened it; a `.generated.` file is skipped unread. It also holds the branch boundary, over every consumer document: a `.prompt.md` anywhere, and an `INDEX.md` under `frameworks/`. Citing a path under `scripts/`, a `AGENTS.md` under `contracts/` or `frameworks/`, or `frameworks/PACKAGING.md` sends a reader somewhere the router promised they would not have to go. `CONTRIBUTOR_PATHS` carries a reason per shape, and `BRANCH_SWITCH` carries the single carve-out: the root `SKILL.md`, which names the contributor branch because naming it is how it sends a contributor away. Nothing below it has anybody left to redirect, so a document there needing an exception is a rule stated on the wrong branch. **`RULE_OWNERS` is the same boundary run the other way, on CONCEPTS rather than paths**: a rule is assigned to one branch with its reason, and the gate fails the phrase appearing on the other. It is a register rather than a mechanism, so it covers what is declared and nothing else, and what is not declared is unheld and said to be; an entry no document on its own branch states any more fails as a stale registration. It exists because a `R4 violation` written into a contract's `description` reached a published `.d.ts`, where a consumer read a rule number with no way to learn what it meant. **`FOREIGN_CODE` runs the same boundary over what a document OFFERS rather than what it says**: a fenced example writing another design system's markup fails, and prose naming one passes, because a Don't saying what Arena is not teaches nobody to install it while an example is the half a reader copies. The two halves are the two the Markdown lexer already separates, so a code span is prose's neighbour and a fence is not. **It also holds the one count a consumer document carries**: each layer's `PACKAGE.md` states how many components the package ships, and `COMPONENT_COUNT_CLAIM` compares that number against `frameworks/Components.json`. The count stays because the npm page is where a reader meets it first, and it is held because the two pages had drifted four and nine components behind the tree with every gate green. |
| `check-graph.ts` | the declared script graph disagrees with itself: a script under `build/`, `generate/` or `check/` that neither declares a node nor is named in one of the two lists that say it is out, an entry in either list that has since subscribed or gone, a node whose name is no npm script, a `feeds` naming no node or naming itself, a cycle, an artifact two nodes write, a node reading nothing that is there, or a spec whose directory holds no file at all. **The rule it exists for is the unsubscribed reader**: node B reads what node A writes and A does not list B in `feeds`, so a run would keep B's last answer over an artifact A has just rewritten. Both halves are held, so a `feeds` entry no artifact carries fails too, an edge nobody maintains being the same defect read backwards. A spec matching no file today whose directory IS there is reported and allowed: refusing it would mean a declaration can only describe the tree as it stands, and the first file of a new kind would be read by nobody. What it asserts lives in `scripts/graph/graph-problems.ts`, with the rest of the graph; this file is a print and an exit. |
| `check-portability.ts` | a script assumes one operating system. Every rule is a **ban with a named owner**, never a judgement about whether a construct is correct, and that is what keeps its false-positive rate zero by construction: it does not ask whether spawning a bare name is wise, it asks where that may live. `process.platform` belongs to `lib/arena/platform.ts`, an absolute path to the browser candidate table, a bare-name spawn to `host-binary.ts`, a `node_modules/.bin` path to `node-bin.ts`, a process-group signal to `chromium.ts`, a raw `symlinkSync` to `platform.ts`, and a separator spelling or a prefix containment to `utils/posix-path.ts`. Locale ordering is owned by **nowhere**, and that empty list is the claim. **A stale owner fails too**, so an exception cannot outlive the thing it was written for. The subject is scripts and **not suites**: a suite naming `win32` and a `C:` path is doing its job, and the win32 branches are covered from a Linux runner precisely because it does. Matches are filtered through the same lexer `check:docs` uses, so a construct named in a comment is described rather than performed; the two rules whose construct **is** a string say so in their own declaration, since skipping literals for those would skip the rule, and its suite plants one violation per rule because a gate only ever seen to pass is a gate seen to do nothing -- that fixture is what caught the `.bin` rule not firing at all. It also holds `pr.yml`'s matrix equal to `ci/arena/supported-os.ts` -- **names and blocking flags both**, so a leg cannot quietly stop counting nor a supported platform quietly stop gating -- and holds `pr-gate`'s `needs` equal to **every other job in that file**, stated as the complement rather than as a list somebody keeps in step: a job the one required check does not name is a job whose failure branch protection never hears about, which is exactly what a matrix living in a workflow of its own bought, since `needs` cannot cross workflows. It fails unless **exactly one** workflow names `CHROME_PATH`, exporting it everywhere being what made the candidate list unreachable. A separate set of rules is about the tracked **path** rather than the file, which is why no gate over content could see them: a **reserved device name** (`con`, `nul`, `com1`, whatever the extension or case), a character NTFS refuses, a segment ending in a dot or a space that Windows silently rewrites, a **case-only collision** that a case-insensitive filesystem resolves by overwriting one with the other, and a path past `MAX_PATH` once `CLONE_ROOT_BUDGET` is spent. None of those exist today, and the emptiness is the claim; the run states the longest tracked path against the budget so the margin is a number rather than a hope. |
| `check-generated.ts` | a file whose header says a script writes it does not say so in its name, or a `.generated.` file is neither tracked nor covered by a reason-carrying ignore entry. Both directions fail silently otherwise: an unnamed output is read as hand-written, and an ignored payload file ships a tag whose `intro/styles.css` `@import`s resolve to nothing. |
| `check-skill-spec.ts` | the consumer branch stops answering the Agent Skills specification: a second tracked file under the reserved name, a skill carrying no frontmatter, a `name` that is not lowercase alphanumeric separated by single hyphens or does not match the directory holding it, an empty or over-long `description`, a frontmatter key neither the standard nor `HARNESS_KEYS` declares, a value that does not parse as YAML because an unquoted scalar carries a colon and a space, or a body over the ceiling the standard recommends. **The count is the assertion rather than a tidiness rule**: a file carrying that name and no frontmatter is not a lesser skill but a broken one to anything that globs for the name, which is what the npm convention does, so seventeen index documents under it were seventeen skills that fail to parse. The subject is what git tracks, since the plugin is served from the tag where nothing runs a build and a file outside the index reaches no reader. **`HARNESS_KEYS` is empty, and the emptiness is the claim**: a key the standard refuses costs every client that validates the frontmatter, and the one this skill carried set `user-invocable` to the value it already defaults to. An entry the skill stops carrying fails as a stale departure. The YAML rule is the one the standard's own reference validator found and this gate did not: the description had read `not the skin: it ships`, which ends a plain scalar and turns the rest into a mapping, so the frontmatter had never parsed. A run finding nothing in the index fails rather than passing over a branch that reaches no clone. |
| `check-skills.ts` | `frameworks/INDEX.md` or a layer's own `INDEX.md` stops matching a fresh emit, or one falls out of the git index. The index tree is tracked rather than built, because the plugin is served from the git tag where nothing runs a build, so a stale copy is a wrong answer handed to every reader of that tag with every other gate green. Tracking is this gate's to assert because `check:generated` scans no `.md`. Fails on an empty declaration too, rather than comparing an index of nothing against an index of nothing. |
| `check-prompts.ts` | a `.prompt.md` carries no `@api` region, or one that does not match a fresh emit from `contracts/api/components/<Name>.json`. A prompt is where a consumer stops reading, so the members have to be stated there; a hand-typed table would be a second copy of the contract that nothing holds, and the fix for a wrong cell is always the contract. Whether a component is contracted at all is `check:api`'s question, so an uncontracted one is counted rather than failed. |
| `check-api.ts` | a layer's implementation diverges from `contracts/api/components/<Name>.json`. **No exception map at all**, deliberately: a contract forbids divergence, so it has nowhere for a second opinion to live. |
| `check-playgrounds.ts` | a fixture under `frameworks/demos/` stops holding against the contract it seeds: a seed the contract does not declare, a value of the wrong type, an enum value outside its declared set, a required member or slot the fixture leaves empty, a bind naming something that is not an event or writing a payload into a member that cannot hold it, or a host that does not mark exactly one place for the component under test. Type-checking a seed is the whole point: a component drawn from a bad seed still draws, so the page renders and lies while every other gate stays green. It also holds the half of the citation rule only this gate can make: a cited `.demo.generated.html` is one a contract actually **emits**, and a bare page filename names something under `frameworks/`, which is the one shape a rename rewrites in every import and in no sentence. Whether a cited path merely exists is `check-citations.ts`'s, which reads every document rather than a layer's. It opens none of them: every check here compares emitted SOURCE, so a page that compiles and then mounts nothing is invisible to it, which DOUBTS.md carries. |
| `check-kitchen-sink.ts` | an arrangement under `frameworks/kitchen-sink/` stops pointing `check-pixel-parity.ts` at the whole library: a component the registry names that no arrangement places, an arrangement naming a component that does not exist, a component placed twice, a `frameworks/demos/` fixture that stops pinning a member its component would otherwise read off the clock or the host's own zone, or an emitted page that is not what a fresh run of the generator writes. Every one of those shrinks the surface the pixel comparison runs over while leaving it green, which is the failure that gate cannot see about itself: it reports zero differences over a page holding nothing exactly as it does over a page holding everything. |
| `check-citations.ts` | a `.md` anywhere in the tree names a repository file that is not there, or cites `path:member()` naming a file that declares no such member. Both defects it was written for had stood with every gate green: a document citing a spec the charter deletes once executed, and a build chain naming a step that had been renamed. A match is judged only when it names a **file**, because prose shortens a path freely and a shortened one is not a claim, and a leading slash is a URL from a site root rather than a repo path. The roots are read from the tree, so a new top-level directory is covered the day it lands, and a run finding none of them fails rather than reporting every absolute path missing, which is the vacuous pass in reverse. `EXEMPT` names what is absent on purpose, with a reason each, and an entry no document cites any more fails as a stale allowance. **A root git ignores leaves that list**, asked of git rather than guessed, because `docs/` exists on the machine a spec was written on and on no clone, so the gate would otherwise scan a different alternation depending on where it ran -- and a gate whose subject varies by environment is the defect this whole rule set is about. Closing that opens the other half, which it also holds: **a document citing a file under an ignored root fails**, since such a citation passed here for the wrong reason, the root not being in the alternation at all, while no clone could follow it. **The walk skips those roots too**, and that half was found by filing a real plan under `docs/` and watching the gate judge it: excluding a root from the alternation and still walking INTO it fixes which paths are recognised and leaves which documents are read varying by machine, which is the same defect with a different subject. `basenames()` skips them for the same reason, or a bare citation would resolve against a scratch file that exists on one machine. |
| `check-agents.ts` | a level on the contributor branch is reached by no chain of links from the router, or a `README.md` is back on this branch. The levels are what the walk finds rather than what a list declares: the list this gate used to carry had gone thirty-five short while reporting itself complete, which is the shape a hand-maintained subject always ends in. **A level nobody wrote is deliberately not a failure**, because the convention hands a reader the nearest level above it and that is a correct answer; a level nobody LINKS is, since proximity is automatic for an agent and unavailable to a reader, so the same tree answers the two of them differently. `emitted()` drops a copy a build left behind, and it is scoped so `scripts/build/` stays in the walk: widening it by one word took five real levels out of the subject with the gate still printing a pass. `SURVIVORS` names every `README.md` kept and why each is not a contributor document, and an entry whose file has gone fails as a stale allowance. |
| `check-agents-spec.ts` | the contributor branch stops answering [the convention published for its filename](https://agents.md), which fixes a file at the root, that name exactly, plain Markdown with no required field, a level resolved by proximity, and a command an agent runs because a page listed it. The convention publishes no validator and no schema, so this gate is the whole of what holds Arena to it and `npx agents-lint` is a third party's second opinion rather than the standard's. **The commands are derived and never listed**: a script whose name carries no colon is an entry point and one with a colon narrows a phase, so the root page has to name each entry point and gains the obligation the day a new one lands. Whether a name a document spells is a script at all belongs to `check-vocabulary.ts:BUN_RUN` and is not asked twice. `DEPARTURES` carries what Arena does differently with the reason, and it fails both ways: a departure the tree makes and nobody declared, and a declared one the tree has stopped making. |
| `check-duplication.ts` | two documents state more of the same sentences than their limit allows: three anywhere in the tree, or `FAMILY_LIMIT` between two components filed under one category. The unit is a normalized sentence of at least `MIN_WORDS` words, compared through an index over every document at once rather than pair by pair, and a **generated region is cut out before anything is compared**, because it is one source rendered into many files and leaving it in made every prompt overlap every other one through the same emitted line. Two shapes are legitimate: `sameSubject`, two documents with one file name, which is a document rendered per layer and a generator question rather than a duplication one; and `sameFamily`, two components stating the rule they both answer to, which is `FAMILY_DEBT`, a real duplication that is bounded rather than paid because a reader opens exactly one prompt and moving the rule up a level would charge every build for a family it is not using. |
| `check-deadlines.ts` | a bare span sits in a wait position, or a suite's budget does not name every deadline its import closure declares. A literal in a case timeout, a `withTimeout` bound or a `sleep` is a number read off whichever machine wrote it, so it is right where it was written and silently wrong everywhere else: it expires early and reports its subject absent, sending a reader into the component that has no defect. A budget under one of the deadlines it can spend abandons the callback with its subject still running, and every file loaded afterwards then reports an error naming neither. The closure is read as **text** by `scripts/graph/script-closure.ts` and never imported, because importing a script to read it runs it. Both maps carry a reason per entry, and the paired suite asserts on them by name. |
| `check-consumer.ts` | the `arena-to-prod` command a package ships stops doing what the npm page says it does, run against a real fixture project rather than reasoned about. It assembles each package, installs it into a temporary project, runs the CLI and reads what came out: the theme sheet's import chain, `"components": "auto"` resolving to the sheets a source actually needs, a component name the package does not ship being reported rather than silently dropped, and a source naming a symbol this package does not export resolving to nothing, since no alias exists to soften it. `DOCUMENTED_LIST` reads the sheet list back out of the shipped `README.md`, so the page and the command cannot drift apart. |
| `check-vocabulary.ts` | a document states a naming convention no file in the tree answers to, cites a sibling by a bare name nothing carries, tells a reader to run an npm script `package.json` does not declare, names a `README` on the branch whose one filename is `AGENTS.md`, or hands over a `find` whose pattern matches nothing where it looks. Each of the five had a live defect the day it landed, and every one had stood green: the claim is prose and the subject is the tree, so nothing was comparing them. A convention is the expensive one, since a reader hunting for the file it names cannot tell a stale document from their own mistake. `NAMED_BUT_NOT_HERE` carries what is named and correctly absent, the consumer's own files and what the assembled package ships, and `README_MEANS` the documents that mean the page npm shows; a deliberate absence is read from `check-citations.ts`'s own map rather than declared twice. Reach is the whole tree for the same reason `check-citations.ts`'s is: a gate names the shape it reads, never the shape it sits beside. |
| `check-routes.ts` | a declared reading route costs more than its budget, names a stop that reaches no document, or has fallen so far under its budget that the number stopped applying pressure. `ROUTES` is the registry: each entry is an ordered list of stops, and a stop is a pathspec charged for the **largest** file it reaches, so a route is measured at the worst case a reader can meet rather than at an average nobody experiences. It is the only gate that measures a document by what reading it costs somebody else, which is why the budget carries its reason as a string: a route grows by a paragraph that reads as an improvement at the place it is written. |
| `check-community.ts` | the surface a stranger meets before any code stops holding: a declared outward-facing file nobody wrote, the governance policy stated in a second document or in none, a contact link naming a path the default branch does not carry, or a `context7.json` that has drifted from the router. `OUTWARD` names each file with the reason it exists, because none of them is reachable from the router and nothing else would notice one going. The two failures it was written for are both silent: a repository that reads as maintained and answers 404 to the reporter who followed its own contact link, and an indexed document the consumer branch never meant to hand over. Context7 has no router, so what it indexes is what it hands back, and every contributor document reaching the index is a contributor answer to a consumer question; an exclusion covering nothing fails as a stale allowance, in both directions. **Which names it guards is derived and never listed**: `contributorBasenames()` takes every document the walk finds, drops what a build emitted, what the config already excludes by folder, what `check-docs.ts:isConsumerDocument(repoRelativePath)` calls the other branch's, what `OUTWARD` sends to a stranger, and the one README that belongs to neither. The list it replaced named four while the tree carried six, and the two it was short of were a chart family's own tour and a page written the same session, both of them indexed and neither of them for a consumer. Every string in `rules` is required to be a span of `SKILL.md`, compared with runs of whitespace flattened, so the copy cannot go quietly false and rewrapping a paragraph is not a failure.. **It also holds the file to the schema it declares**: that schema sets `additionalProperties` to false, so a key outside its set is not one field ignored but a document that fails to validate whole, and what gets indexed is whatever the service falls back to. The set is written here because the schema is published rather than vendored, and a key it gains is a key this list has to gain with it |
| `check-site.ts` | the published site stops holding to what it claims: a page pointing at an asset the output does not carry, a page the manifest declares and the build dropped, one published that nothing declares, a sitemap missing an entry, or a CNAME for another domain. The first is load-bearing and `intro/AGENTS.md` says why nothing else catches it: a broken path fails silently in both directions, and an unstyled page that fits its box passes a look. The shape a static host breaks and a dev server hides is a directory answered at request time with a listing. It SKIPS when `dist/site/` is absent, since a walk of nothing reports every link resolved; what makes a dropped playground visible is `site-pages.ts` asking the component map rather than the filesystem. |
| `check-icons.ts` | a `ph-` class name in the tree is not a Phosphor glyph, or is a glyph the weight beside it does not carry. A contract takes an icon as a string, and a string nothing checks is a typo that renders an empty box, with no error and no failing gate. The truth is read out of the installed `@phosphor-icons/web` rather than typed here, because a list of 1500 names ages the first time the package does, and finding no stylesheet is an explicit failure rather than a pass over nothing. `SCANNED_ROOTS` is the scope and `EXEMPT` is empty on purpose: a name Phosphor does not have is a typo rather than a case. |
| `check-behaviour.ts` | a component declares no `<Name>.behaviour.json`, names a pattern or requirement that does not exist, or the two layers disagree without saying why. A green run is a **coverage** claim, never an accessibility one. |
| `check-compliance.ts` | a coverage claim in `COVERED` is stale: a suite that no longer exists, or one whose layer key does not match the `SUITE_DIRS` tree it was found under. Coverage is partial by design; the gate never demands totality, only that every claim is true. |
| `check-contracts.ts` | `contracts/` stops holding the shape `contracts/AGENTS.md` describes: a stray file in a level, a level missing its normative document, an undeclared inner directory, or a fourth directory beside the three. `SHAPE` is the declaration, and `design` is the one level whose normative statement is two documents, `AGENTS.md` for what a value means and `TokenTypes.md` for the shape it arrives in. It is `check-structure.ts`'s analogue for `contracts/`. |
| `check-structure.ts` | a component is declared in two categories, sits in a category `frameworks/Components.json` assigns elsewhere, is named by no declaration, or is present in no layer. It says nothing about whether the category is the **right** one. |
| `check-script-tokens.ts` | a `Tokens.generated.*` module disagrees with the DTCG source or the CSS, a `script: true` flag is orphaned, or `ArenaCatSlot` stops being exactly `1..catSlots` in order. |
| `check-intro-generated.ts` | a page bundle under `intro/` does not match its source, or a page loads a module entry that is not a bundle. Those bundles are **tracked**, because the Claude Code plugin is served from the git tag and nothing there runs a build, which is the same reason `contracts/design-generated/` is tracked; a tracked build product is a promise, and this is what keeps it. The second half is the load-bearing one: a page whose `<script type="module">` pointed back at its own source would serve whatever that source imports, which is what kept `css-decls` and `token-preview` out of TypeScript until `build:intro` existed. Bundling is Bun-only, so it reports SKIP where Bun is missing, on `check:vendor`'s terms. |
| `check-script-types.ts` | a `.ts` under `scripts/` does not typecheck, one of them takes syntax bare node cannot strip, or the project's globs stop reaching a file that is on disk. The tooling answered to no compiler before this, unlike both framework layers. The project sets **`strict`** as a bundle, the way both framework layers do. It did not start there: the seven cost nothing like each other, and the enumeration was how each one's price got measured. For the record -- `strictFunctionTypes`, `strictBindCallApply`, `noImplicitThis` and `alwaysStrict` cost **nothing at all**, `useUnknownInCatchVariables` seventeen catch clauses, `noImplicitAny` **1,643** annotations and `strictNullChecks` **970**. The order between the last two was not free: evolving-array inference needs `noImplicitAny`, so turning `strictNullChecks` on first surfaces hundreds of `never[]` errors the other flag erases. The paired suite asserts that none of the seven is named individually, since naming one can only weaken what `strict` already turns on, and `noUncheckedIndexedAccess` is on beyond it, the last flag either framework layer had that this one lacked. It cost **716**, because a tooling script reads `arr[i]` and `map[k]` constantly; most of that was a suite matching a regex against `problems[0]` and a parser reading a capture group, which is why `utils/captures.ts` exists. A `.mjs` is resolved and never checked, which is what the two vendored copies need: turning `allowJs` off would make three `.ts` imports unresolvable rather than unchecked. `erasableSyntaxOnly` is the load-bearing flag, and the paired suite asserts it by name along with `strict` and `checkJs` at their current loose values, so lifting either is an edit to that file rather than a drift nobody voted for. The unreached-file count is the vacuous pass this gate can take: a tsconfig matching nothing compiles nothing and reports clean, so what the project reached is counted against what is on disk rather than trusted. |
| `check-script-reach.ts` | a path into `scripts/` that is named from OUTSIDE it stops resolving. Nine sources under `frameworks/` and `intro/` import tooling modules and `package.json` names one per npm script, and nothing saw either: `check:script-types` stops at `scripts/` and `script-imports.test.ts` scans only inside it, so a move was silent from out here. **The path is the cheaper half and not the one that failed**: `pascal` left `layers.ts` for `utils/case.ts` while `layers.ts` stayed exactly where it was, so every path still resolved and a suite reported `not a function` instead. This reads the bindings too, by importing the target and asking what it exports, which is safe precisely because a gate guards its `main()` with `isMainModule` rather than running on import. Two shapes reach in: a literal naming `scripts/...`, in code or in prose, and `join(ANCHOR, 'a', 'b')` inside an `import()`, which the Angular suites use because they run from the ngc emit where a relative specifier would point somewhere else. The anchors are **read from `frameworks/angular/test/Compliance.ts`, where they are declared**, rather than repeated here, so a new one is covered the day it lands; one this cannot resolve is a problem and never a skip, because a silent skip is the exact failure the gate exists to end. |
| `check-duplicate-constants.ts` | the same module-level named numeric constant is declared in **both** framework layers. Generated output is out of scope: a file a script writes into every layer is one declaration rather than two, it cannot drift between them, and the gate holding it to its single source is the one that would notice if it did. |
| `check-dimension-literals.ts` | a framework layer writes a bare literal in a property the token layer governs. `EXEMPT` and `PASSTHROUGH` are asserted by name in the paired suite, so changing either is a change to both. |
| `check-manifest-states.ts` | a manifest slot carries a `hover:`/`focus:` state modifier no contract it covers declares in `affordances`, or a component that draws by hand implements a state its contract does not declare. Both halves read the contract and neither reads the other layer; both run one way only, because a declared affordance a layer leaves to the child it composes is not a divergence. A layer that realises an affordance by rendering the manifest's own class has no answer of its own to give, and that is now both layers wherever a component renders its recipe, so the react half reads `HAND_DRAWN` rather than every component: an empty `HAND_DRAWN`, or one of its members never opened, is a failure rather than a clean pass. `MANIFEST_COVERS` and `HAND_DRAWN` both live in `scripts/lib/tailwind/manifest-surfaces.ts`, because two gates read them and either owning them would make the other import in a cycle. This checks **states only**, and nothing about colors, sizes or slot structure. |
| `check-appearance.ts` | a component in scope does not render the manifest that draws its surface, in either layer, or the React layer types a style property out by hand. The literal half's rule needs no list of governed properties, because a style object holds nothing else: **a property whose every branch is a literal belongs in the manifest, and one that reads an identifier or an interpolation is a runtime computation and stays**. That is what tells `ArenaCalendarEvent`'s surviving `color-mix` from a `background: 'var(--crimson)'`. It reads inline `style={{…}}`, a constant annotated `React.CSSProperties`, and an object returned from a function annotated the same, skipping `dist/`. `EXEMPT` is empty, and that emptiness is the claim. Three blind spots are declared rather than closed: a style object assembled with `Object.assign` or a computed spread, a literal reached through an unannotated lookup table, and Angular's `[style.x]="<literal>"`, which is the blind spot `check-dimension-literals.ts` already declares in its own header. |
| `check-parts.ts` | an element carrying a slot class carries no `data-arena-part`, in either layer, or the two layers reach different parts from one manifest. The hook is what a style plugin selects, so a slot that reaches the DOM without one is a decision nobody outside this repository can answer differently. It reads both layers as text and walks the covering manifest's sources, so a family drawn from one manifest is measured whole: an element is the opening tag around a class expression, a React object literal that carries a `className` entry, or an Angular `host` binding. An expression choosing between two slots is one element and takes one part, because a variant of a slot is the same element drawn differently. One blind spot is declared rather than closed: a class string assembled inside a helper names its slot in the helper and not on the element, so a site reading one is asked for nothing. **The symmetry half is the sharper one**: a part is one contract across both layers, so a style plugin painting one only React draws would make two pages out of one manifest, and nothing saw that until `complete` painted through every hook and `check:pixel-parity` compared the two. Draw the same element in both, or take the slot out of the manifest. |
| `check-layer-independence.ts` | a file under `frameworks/<A>` names layer B or one of B's source files, by import or in prose. `ALLOWED` and `EXEMPT` are both empty, and that emptiness is the claim; the one authorised edge is `ALLOWED_SPECIFIERS`', a page **linking** the compiled CSS under `frameworks/tailwind/consume/`, and a pattern there matching nothing fails as a stale allowance. All three are asserted by name in the paired suite. A citation is caught in prose as well as in an import, because prose is where such a coupling mostly lives, and a reference is judged by where it **lands**, so a relative `../../../tailwind/` is caught as surely as the layer's full path. |
| `check-focus-trap.ts` | a modal panel's interior lets Tab escape, in any layer that binds `dialog-modal`. Drives real Chromium over each declared page and presses a real Tab, which is the one thing a happy-dom suite cannot prove; without a browser it cannot run, which the declared strict setting makes a failure rather than a skip. Each page opens its panel from its own fixture, so no walk depends on finding a button by its copy: a page whose wording moved would otherwise be walked with nothing open and report a trap that holds. |
| `check-pixel-parity.ts` | a kitchen-sink page is not painted identically by every layer. Captures the pair in real Chromium, in both themes, and fails on a single differing pixel: there is no baseline, because the question is whether the layers agree with each other rather than with a blessed image, and no blanket tolerance, because one browser renders both pages and a threshold everywhere would license exactly the move this exists to catch. **`ALLOWED` is the one relief and it is declared per sink, bounded on the pixel count AND on the channel delta, and carrying the measurement behind it**, so a wider move is never absorbed by a narrow allowance; an allowance the run does not spend is stale and reported, the shape `SIZE_ALLOWANCE` has in `check-docs.ts`. `default` carries none: the appearance a consumer installs is identical to the pixel in both layers, and the one entry there is records where the two quantise a shrink-to-fit box to a different 1/64 of a pixel, which neither layer can close because the element carrying it is the component itself in Angular and a div in React. | `check-shared-arithmetic.ts` | two copies of one module, authored at the same path in both layers, stop agreeing on a function they both export. `PAIRED` is the list of the modules written twice, and nothing held any of them together: `check:duplicate-constants` reads module-level **numbers**, so an exported function is invisible to it, and a calendar whose layers disagree by arithmetic draws two different schedules from one set of events. Bodies are compared with their whitespace normalised, so a signature may differ where a body may not, which is the whole distinction: `DIVERGENT` carries the ones that genuinely differ, each saying what the two do the same and what they spell differently, and **fails on an entry whose two bodies have since been reconciled**. |
| `check-packages.ts` | the `arena-to-prod` CLI that ships inside both npm packages stops emitting what Style Dictionary emits, or an assembled `dist/` is not registry-standard: a version out of step with `plugin.json`, an `exports` target that was never emitted, an install script, a missing README, or Phosphor bundled rather than declared a peer. ## What `check-dimension-literals.ts` reaches

A value passes when it is `var(--token)`, a `calc()`/`min()`/`max()`/`clamp()` over one, zero,
or a unit the token layer does not model: `%`, `ch`, `fr`, the viewport units and the angle
units, since DTCG admits only `px` and `rem` in a dimension, plus `s` and `ms`, which this gate
alone tolerates. **The same three shapes are what a Tailwind bracket may hold, and the two gates
share the same unmodelled-unit list**, but they are not one list: this gate additionally
tolerates `s`/`ms` and the bracket gate does not, because `--dur-*` and `--loop-*` model
duration.

The scan reaches four kinds of site: a JS declaration, a template literal's interpolation, CSS
injected as a string, and an SVG presentation attribute in `prop="value"` form. An expression
binding, `r={hover ? 5 : 4}`, is outside all of them. A literal reached through an
intermediate local variable is still caught, but only when that identifier is used bare (no
member access, no call, no arithmetic) at the governed site.

It scans `.jsx`, `.ts` and `.tsx` under `frameworks/`, not `.html`, and nothing under `intro/`,
so those pages stay clean only because they are tokenized by hand. The `*.card.html` specimens
under `frameworks/tailwind/` are the one family of unscanned pages that stays clean
structurally: every class they render comes from the manifest through `classesFor()`.

**Two blind spots are known and neither is fixed**: a kebab-case SVG attribute, and Angular's
`[style.x]` binding form, which sits outside all four scanners. This is why a chart drawing geometry
writes its static styling as camelCase `[style]` **objects**: in that shape
`strokeWidth` and `fontSize` are judged as themselves, which is strictly more coverage than an
attribute.

A handful of sites are exempt by name with a reason each: read `EXEMPT` for the current set
rather than a count. A stale exemption fails the gate itself, and a change to `EXEMPT` or
`PASSTHROUGH` is a change to `check-dimension-literals.test.ts` too, since that suite asserts
on both maps by name.

Every `X.test.ts` beside a gate covers that gate. Three suites here name no gate:
`browser-modules.test.ts` covers the `intro/` runtime modules and the two `scripts/`
modules they reach,
`components-categories.test.ts` covers `frameworks/Components.json`, and
`script-imports.test.ts` covers every non-suite script's relative specifiers and the shape of
its main guard. All three are claims about the repository root, which is what makes them
`arena`.

**A module an `intro/` page imports stays `.mjs`, and nothing there may be TypeScript.**
Those pages are ES modules a browser loads over HTTP, and there is no build step between the
git tag and the page, which is the reason `contracts/design-generated/` is tracked in the
first place. Two modules are reached that way today, `lib/arena/css-decls.ts` and
`lib/core/token-preview.ts`, and `browser-modules.test.ts` reads that list off the imports
rather than carrying a typed copy. This is the one rule here a passing suite could otherwise
hide: node strips types and would resolve a `.ts` import happily, while the browser gets a
file `static-server.ts` has no MIME type for and the page fails with every gate green.

**A script decides it is the program by comparing `process.argv[1]` to
`fileURLToPath(import.meta.url)`, never by matching its own filename.** The second form reads
as equivalent and is not: it is a claim about the file's own name, so renaming the file makes
it false, `main()` stops running, the process exits 0 having read nothing, and `check-all`
reports that as PASS. `script-imports.test.ts` holds the rule and carries the only exemption,
the two `validate-palette.mjs` copies, which are vendored verbatim and re-vendored rather than
patched; that exemption fails if either stops carrying the guard or stops saying it is
vendored.
