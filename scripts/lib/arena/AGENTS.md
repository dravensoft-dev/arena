# scripts/lib/arena/

What belongs to no one layer: the parsers, the browser harness, and the tree's own facts.

| module | why it exists |
| --- | --- |
| `repo-root.ts` | The repository root, derived once. Every script imports it from here rather than counting `..` from its own location, so a script's depth under `scripts/` is not part of what it has to get right. **The one place that counts**, which is why moving this file needs care. |
| `artifact-cache.ts` | A derived answer kept under `.cache/artifacts/`, so a step that spawns a compiler pays it once for a given set of bytes. **It is not the graph's cache and shares nothing with it**: `graph/state.ts` keeps stamps and decides whether a NODE runs, this keeps the answer a step would recompute, under its own directory and its own `VERSION`, and neither reads the other's files. Two rules are what make it safe for a gate to read one. **The digest covers every input BYTE and there is no stat filter**, which is the deliberate departure from `graph/inputs.ts:stampOf`: the graph's blind spot, a file rewritten to the same size and the same mtime, costs a step that fails to re-run, and here it would cost a gate a wrong answer, so the suite plants exactly that rewrite. And **only an answer the builder returns is written**, a `null` meaning refuse, so a verdict that came out of a broken install re-runs rather than becoming permanent. An entry is therefore never authoritative: a miss recomputes and a hit is the value a miss would have produced, which is why no gate becomes downstream of another and `check:graph`'s rule that a gate declares no `writes` is untouched. `cachedReading` is for a step that DISCOVERS what it read, which is every compiler: the entry carries the reach the last run reported, so a file that was never a candidate still invalidates. Nothing here is fingerprinted by the graph or counted against a declaration, since `.cache` is in `graph/inputs.ts:SKIPPED_DIRECTORIES` and `.cache/**/*` in `graph/audit.ts:NOT_AN_INPUT`. |
| `arena-scripts-vars.ts` | Every environment variable the scripts read, declared once so a test run or a CI run needs no exports. `arenaEnv()` lays the declared values under the real environment, which wins, so a one-off override stays a shell prefix rather than an edit to a versioned file. `skipExitCode()` is the single reading of `ARENA_CHECK_STRICT` and `CI`, and **`cannotRun()` is the single spelling of what a gate does with it** -- the four skippable gates had drifted into three, so on this repository's own strict default three failed and the fourth skipped. Strictness lives here and not in `chromium.ts` because it is a fact about rigour and not about browsers. **`CHROME_PATH` is deliberately absent**: a declared default is not an override, and laying one under the environment made every machine look like one where a person had named a browser. |
| `layers.ts` | `LAYERS`, `NON_LAYERS` and `emittedTree()`: what a layer is and where the Angular emit sits. An **exhaustive enumeration**, deliberately not a walk of `frameworks/`, so a layer renamed or removed wholesale becomes loud instead of quietly leaving scope. The two name shapes a gate reads a layer through used to live here and are now `kebab` and `pascal` in [`../../utils/case.ts`](../../utils/AGENTS.md), because neither knows it is naming a layer: a directory name derived from a PascalCase one is still **a function, never a table**, and that has not changed. |
| `comments.ts` | Lexes source, so a `//` inside a string, a regex or a template literal is never mistaken for a comment, and a `@ts-`/`eslint-` directive is a directive rather than the file's one allowance. `literalRanges()` reports where the literals are so a second reader can ask whether a match sits inside one: that is what tells an import a generator WRITES from one it performs. It reports ranges rather than erasing them, because a specifier is itself a string, and erasing strings would erase the very thing the resolver reads and leave the scan silently reporting nothing. Kept dependency-free so it runs under plain node. |
| `markdown-prose.ts` | Splits a Markdown document into its prose runs, one per line, so the punctuation rule never judges the code a document quotes. Both skips are lexed: a fence closes only on a run of its own character at least as long as the one that opened it, and a code span only on a backtick run of exactly its own length, which may be lines below. Kept dependency-free so it runs under plain node. |
| `css-decls.ts` | Parses a stylesheet into selector → declaration maps. Read by the token drift gate and by the Overview page, so both judge the same text the same way. It reaches a browser through `build:intro`, which bundles the page that imports it; before that step existed it had to stay JavaScript. |
| `api-surface.ts` | Reads a layer's declared API surface out of source text, by regex. A shape it cannot read **throws** rather than going silently missing from the member list, because a member absent by accident and a member absent by design look identical downstream. |
| `behaviour-contracts.ts` | Loads and validates the behaviour patterns and each layer's bindings. `bindingCases()` is the **single** place the flat and cased binding shapes are reconciled. `BehaviourBinding` is the document those functions read, and two of its facts are only visible from the suites: an exception's `reason` is optional, because reporting an exception that has none is what `validateBinding` is for, and a `BindingCase`'s `pattern` may be undefined, because a binding that names none is exactly the one the gate must catch. Both were declared required and neither is. |
| `playground-model.ts` | Derives a component's playground from its API contract and its `frameworks/demos/` fixture: which knobs exist, what each starts holding, whether it starts bound, and how it round-trips through a URL. Pure and layer-neutral, and the **single** place any of that is decided, so the two layers cannot disagree about a control. A form it cannot model throws, because a member missing by accident and a member missing by design look identical on a page. |
| `playground-page.ts` | The demo page every layer serves, built in one place so the two differ in exactly the two lines they have to: what mounts the app, and what the app is loaded from. A page authored per layer would drift in its stylesheet list or its toggle markup, and a difference in the frame reads as a difference in the component. A cross-layer emitter is outside what `check:layer-independence` scopes, being the mechanism that keeps the layers comparable rather than an instance of the coupling. `sheetLinks()` is that stylesheet list: the preflight plus one sheet per surface the page draws, resolved through `manifestFor()` so a compound child links its parent's. |
| `composed-surfaces.ts` | Which components a component renders INSIDE itself, read from every layer's source and **unioned**. A fixture says what a page instantiates and cannot say this, and the answer differs by layer while the page must not: React's `ArenaUnauthCard` composes `ArenaCard` and Angular's draws the same frame from its own manifest. Read from the import graph rather than from a render, so a branch no knob has taken yet still gets its stylesheet. Nothing holds the result, since a real browser is the only place a missing sheet shows. |
| `chromium.ts` | Finds and launches a headless browser from `CHROME_PATH` or the usual paths, and decides for every gate that drives one what its absence costs -- `browserOrExit` is that decision, made once, rather than the three spellings the gates had. **`CHROME_PATH` is terminal, not a preference**: set and pointing at nothing, it reports that rather than falling back, because a path someone wrote down and a path that happens to exist are different claims. It is also **no longer declared**, which is what made the fallback exist at all: while `arenaEnv()` supplied `/usr/bin/chromium`, `CANDIDATES.find(exists)` was unreachable on every machine and the two macOS entries in that list had never once run. The list is now keyed by platform and, on Windows, **built from the environment** -- `ProgramFiles`, `ProgramW6432`, `ProgramFiles(x86)`, `LOCALAPPDATA`, read case-insensitively because `arenaEnv()`'s spread loses `process.env`'s case-insensitive proxy. Edge is in all three lists: it is Chromium, it speaks CDP with these flags, and on Windows it is already installed. The platform is a **parameter**, so a Linux runner covers the win32 and darwin lists. **Teardown asks, then insists, then removes**: a signal, a **short** grace, a forced reap of the tree, and only then the profile. The grace is short because a browser signalled the instant it reports its endpoint is still starting its subprocesses and may never answer: waiting the full exit timeout before escalating stalls every gate's `finally` block, four times a sweep, and it is what timed out a suite on a runner at 5001ms while passing here at 145ms. Its suite covers that with a stand-in that **ignores TERM outright**, so the escalation is proven on a machine with no browser at all. The order is the point -- the previous spelling removed the directory on the line after the signal, racing the browser's own writes, which succeeds by luck on Linux and fails with EBUSY on Windows every run. The forced reap is `process.kill(-pid)` on POSIX and `taskkill /T /F` on Windows, where a negative pid means nothing and the tree would survive. A spawn that **failed** counts as exited, or `kill()` waits out both timeouts for a process that never existed. `--no-sandbox` and `--disable-dev-shm-usage` are **linux only**: they are container idioms, and the first is a real weakening on a real desktop. |
| `domains.ts` | The five phase domains every script sorts itself into, declared once so a gate and its runner cannot disagree about which job runs it. It also declares the style plugin lists and the `isScript`/`isSuite` pair that says what counts as either, because **four separate scanners walk this tree** -- `check-all.ts`'s `testFilesUnder()`, `summarize-tests.ts`'s `suiteDomains()` and `script-imports.test.ts`'s `scriptsUnder()` -- and a suffix one of them stops recognising does not fail: the file quietly leaves that scanner's scope and keeps every gate green. `domainOfTestPath()` classifies by directory rather than by suffix, so it needed nothing for the migration and is stated here as the reason it needed nothing. Since the migration finished the two lists differ and the difference is the point: **`SUITE_EXTENSIONS` is `.ts` alone**, because nothing loads a suite and so no suite can earn an exception, and **`SCRIPT_EXTENSIONS` still holds `.mjs`**, because `STAYS_JAVASCRIPT` names four modules that remain JavaScript for reasons this repository cannot change, and a scan proving specifiers must still reach them. That map is asserted **exhaustively in both directions**: a fifth `.mjs` fails as an exception nobody argued for, and an entry whose file has been renamed fails as a stale one. |
| `cdp.ts` | The Chrome DevTools Protocol dispatcher the viewport gate drives the browser with. |
| `package-exclusions.ts` | What never ships: the names and the patterns each assembler's walk skips, and the `excluded()` that answers with them. It sits apart from the assembler that honours it because the publish guard asks the same question in a job with no install, and reaching the rule through `package-assembly.ts` meant loading typescript, tailwind and the token generator to get it. Bun answered those from the registry at a major the tree does not pin, the import threw, and the guard republished both packages from a diff of the whole tree. Nothing here imports anything; `package-assembly.ts` re-exports all three names, so the rule is still found beside the copy. |
| `package-assembly.ts` | What both npm package builds share: the exclusion list deciding what never ships, the copy that honours it, the CSS chain each package carries, and the manifest template that stamps the version from `plugin.json`. `arena` because it reads two framework layers and the repository root. It compiles nothing; each layer's builder does that with its own toolchain. Its suite also holds the one rule the CLI tree cannot break: `copyCli` copies `generate/core/arena-to-prod/` whole into `bin/` and nobody compiles it, so a specifier climbing out of that directory resolves here and to nothing in the package. The assertion reads the copied files rather than the sources, because that is the tree a consumer runs, and it exists because such an import once shipped and only `check:consumer` over a freshly assembled `dist/` caught it. |
| `component-map.ts` | What a consumer writes and the component sheet it costs, derived per layer and carried in each package as `components.json`, so `arena-to-prod` can resolve `"components": "auto"` without guessing. The link is **derived, never conventional**: there are fewer sheets than components, since a row, an item and a tab wear their parent's, so it is read off the manifest each component's styles import. It also closes what Arena draws for the consumer, since a table renders a pagination and a select and a subset missing them is a silent unstyled render. **Each layer gets its own map because they differ in fact**: React's confirm dialog renders an `ArenaButton` and Angular's draws its own out of its own manifest. |
| `child-output.ts` | A spawned child's output, read from a file rather than a pipe. **Not to be confused with `captures.ts` in [`../../utils/`](../../utils/AGENTS.md)**, which is about regex capture groups; this one is about child processes. A child that writes its results and then calls `process.exit()` -- tsc, ngc and every other JavaScript compiler this tree spawns -- exits before the tail of stdout has drained, and `spawnSync` reports that short read as a whole one: **status 0, no error, output simply missing its last lines**. Nothing downstream can tell a truncated answer from a complete one, which is what makes it worth a module rather than a comment. The loss is a **race**, so it survives local runs and lands in CI: the real `--listFilesOnly` listing came back short in **2 of 30** runs here, and in CI `check:script-types` read it 16 lines short and reported 16 files as unreached by globs that reach them, which is a gate accusing the tree of the tooling's own bug. A file descriptor the child inherits is written synchronously and has no buffer left to lose. It costs a temporary directory per call, which is why it is for the spawns whose output is **read** and not for the ones that inherit stdio. Its suite provokes the loss with one oversized write instead of reproducing the race, so restoring a pipe underneath fails on every run rather than one in fourteen. |
| `contract-shapes.ts` | The shape `contracts/api/` holds on disk, so the scripts that read those files agree about it. Every one of them reaches a contract's members through `Object.entries()` over a `JSON.parse`, which hands back `unknown`, and a gate that then reads `.form` off an entry is making a claim about the file it never states. `memberEntries()` and `fieldEntries()` are that claim, in one place, and the first two consumers are `check:api` and `check:playgrounds`. It describes the **source** contract and never the API a consumer sees: `Api.generated.ts` is emitted from these files and is a different document for a different reader. The keys are derived from the contracts themselves, with one exception stated in the file: `MEMBER_FORMS` is read from `contracts/api/MemberForms.md`, because `consumerData` is a legal form no component uses today and deriving the eight from the instances would silently drop it. `check:api` reads the list from here rather than repeating it. It carries **two** shapes and the difference between them is the point: `ComponentContract` is the document a valid file holds, and `ContractCandidate` is what a reader actually receives -- every key optional, `form` an unchecked string -- because the gate that validates a contract is by definition handed the ones that fail, and its suite passes `form: 'callback'` on purpose. All seven readers take the candidate. |
| `typecheck.ts` | Spawning tsc over a tsconfig, for the two gates that do it: `check:react-types` over the React layer and `check:script-types` over the tooling itself. **`verdictFor` is what both call, and it spawns nothing when nothing moved**: the compiler is the most expensive thing either gate does, measured at 12.1s and 852MB peak for the React project and 15.5s and 712MB for the tooling one, against 0.1s and 25MB when the verdict is held. It goes through `artifact-cache.ts` rather than the graph because `check:script-types` is in `graph/nodes.ts:NEVER_SUBSCRIBES` and will never be kept by a fingerprint: its subject is the closure of nearly every node, so it is dirty whenever any of them is, and it pays the full spawn on every sweep. The key is a different question from the graph's. It is the bytes of every file **tsc turned out to read**, which `projectFiles()` reports and the entry carries forward, unioned with the candidate list on disk, so a file that JOINS the reach invalidates as surely as one that changed inside it. **Only a passing verdict is kept**, so a red one out of a broken install re-runs. Hashing the 621 files the tooling project reaches costs 18ms, which is the whole price of the answer. A library rather than a function hanging off either gate, because a gate importing another domain's gate would make the domain grid a lie, and `lib/` is the one direction always allowed. `arena` by the vocabulary rule: tsc and tsconfig belong to no single layer. `check:angular` keeps its own runner, sharing the shape and none of the code, because `ngc` emits into a temporary tree rather than checking in place. `projectFiles()` is here so a gate can prove its project matched something: a tsconfig whose globs match nothing compiles nothing and reports clean, which is the one way a typecheck gate passes over a tree it never opened. It spawns through `child-output.ts` and never a pipe: `projectFiles()` parses what tsc printed, so a read that silently loses its last lines does not fail, it **answers wrongly**, and the gate then names files the globs did reach. |
| `static-server.ts` | The static file server behind `bun run demos`, and the fixture the card gate loads pages from. Its own suite asserts a real `fetch`, which is why the DOM-free test invocation must stay DOM-free. `resolveInRoot` is the containment rule **both** servers ask -- `serve.ts` consumes it rather than spelling its own, which is how a fail-open prefix comparison and a fail-closed one stopped being two answers to one question -- and it answers a path or nothing, so each caller decides what a refusal costs. A pathname that does not decode is a refusal too, since throwing out of a request handler is a crash and not a 403. |
| `host-binary.ts` | A binary the **host** provides, resolved to a path before it is spawned. Six sites passed a bare name to `spawnSync`, which works on POSIX and is a coin toss on Windows: there is no `git` there, there is `git.exe`, and which suffixes count is `PATHEXT`'s answer rather than node's. Resolving also turns the failure from a status nobody reads into a message, since a spawn of an absent name reports `ENOENT` naming neither which binary nor why Arena wanted it -- so **each caller states the reason** and gets it back in the error. Never for a binary this tree installs; that is `node-bin.ts` and a different question. |
| `node-bin.ts` | The JavaScript entry of a **dependency's** command, read from its own `package.json` rather than taken from `node_modules/.bin`. That directory holds an extensionless shell script on POSIX and a `.CMD` plus a `.ps1` on Windows, with nothing named plainly, so spawning the shim by its path is a file-not-found there. `typecheck.ts` already resolved `tsc` this way and is the shape this generalises; **`ng-packagr` spawned the shim directly**, with no runtime in front of it, which is the same defect twice over. A package declaring several commands must be asked for one by name, because guessing is how a build silently runs the wrong tool. |
| `platform.ts` | **The one module that reads `process.platform`.** Everywhere else takes the answer as a parameter, which is what makes a branch written for Windows testable from Linux: the machine a contributor happens to own stops deciding which half of the tooling is covered. `check:portability` holds the rule and names this file as its one owner, because a second reader is a second place a platform assumption can hide, and hiding is how this repository became Linux-only without anyone writing that down. It carries the identity, and the one operation whose **argument** is the platform rather than its subject: `linkDir` is a symlink on POSIX and a **junction** on Windows, which is a fact about the two operating systems and about nothing that links. A junction needs neither Developer Mode nor elevation, which a directory symlink does, and `check:consumer` builds one into every fixture. A candidate browser path list is the other case and stays with the browser. |

Every `X.test.ts` beside a module covers that module.
