Steps to release a new version x.x.x of Arena

1. Change version docs, four places. This comes first, before any build: the packages are
stamped from .claude-plugin/plugin.json, so a build that runs before the bump writes the OLD
version into frameworks/*/dist/package.json and check:packages reports the difference in the
next step. Each place is named by what it says rather than by a line number, because a line
moves under the next edit and takes the pointer with it in silence:

.claude-plugin/plugin.json          the "version" member
.claude-plugin/marketplace.json     the "version" member
.claude-plugin/marketplace.json     the "ref" member, which names the tag as vx.x.x
README.md                           the "- **Repo/Claude Code plugin**: x.x.x" line under
                                    the "## Latest project artifacts" heading. check-release.ts
                                    finds both by exact regex, so the heading and the label
                                    are the parts that must not be reworded.

verify with:
bun scripts/check/arena/check-release.ts
(expected: every other check PASS, and "tag exists" FAIL with the git tag -a line,
 because the tag is two steps away. This one reads the manifests, the README and git, and
 never the built packages, so it is answerable here.)

2. Rebuild the packages:

bun run build:release

Then run every gate the same way:

bun run check --release

That runs all of them and also reports any gate that failed while the graph would have kept it,
which is a defect in what that gate declares rather than in the gate. A release is the one run
where a wrong declaration has to surface, because it is the run nothing downstream re-checks.

dist/ is git-ignored and no other build touches it, so it holds whatever was last built there,
which after any component work is not what the tree says. check:packages reads both the version
stamp and whether every component Components.json declares is in the emitted .d.ts, so a skipped
rebuild reports itself rather than shipping. It compares dist/package.json against plugin.json,
which is why the bump is step 1: run in the other order and this gate fails on the version you
just wrote, and the only fix is to build again.

3. Generate git tag:

git tag -a vx.x.x -m "Arena vx.x.x"

bun scripts/check/arena/check-release.ts
(all PASS)

git push --follow-tags origin current-branch-name
