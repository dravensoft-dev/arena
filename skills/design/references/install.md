# Installing Arena and wiring its stylesheets

How do I install an Arena package? Which peers arrive with it? How do I import the generated stylesheets in React or in Angular? Why does TypeScript report TS2307 on a stylesheet import? Why does every name start with Arena? Read this once per project, before the first screen.

The support matrix and the peer table are in [`stack.md`](./stack.md). The commands below come from the same manifest ranges.

## How do I install a package?

Pick the package for your layer and your manager. Each command names the package and the peers a project does not have already, with the ranges taken from the manifest. `<angular-major>` is your Angular major.

<!-- @support install GENERATED by bun run generate:support. Edit that script, not this copy. -->

```bash
npm i @dravensoft/arena-react
npm i @dravensoft/arena-angular '@angular/cdk@<angular-major>'
npm i '@angular/router@<angular-major>' '@angular/forms@<angular-major>'   # optional peers, when you need them
```

<!-- @support install end -->

Swap `npm i` for `pnpm add`, `yarn add` or `bun add`. Under pnpm the layout is strict, and every peer is declared rather than assumed. The command that ships with the package resolves the three packages it reads at build through the symlinked store like any other dependency. No hoisting flag is needed.

A required peer is one the package cannot load without. npm 7 and later, pnpm 8 and later and bun install a missing one on their own. Yarn reports it and leaves the install to you.

A peer named with a range on the command line is an explicit install, and the manager writes the highest version in range into `package.json`. So the command leaves the framework unnamed, and your project keeps the version it runs, inside the ranges in [`stack.md`](./stack.md). An optional peer is never installed for you.

The package declares `engines: { node: ">=22" }`, the oldest line Node still supports. The `arena` command is plain JavaScript over `node:fs`, `node:path` and `node:url`. A project on a supported Node installs without an engine warning.

## What comes down with the React package?

The required peers are `react` and `react-dom`, which the project already has. `@phosphor-icons/web` is no peer: Arena ships no icon font.

The package declares three `dependencies`: `@phosphor-icons/core`, `harfbuzzjs` and `wawoff2`. No component imports them, so none reaches a bundle. The `arena` command reads them at build, to cut the sprite from Phosphor's SVGs and to cut each local font.

The package needs no CSS toolchain. Every component's CSS ships compiled against Arena's own class names and tokens. A project running its own utility framework cannot collide with it in either direction.

## What comes down with the Angular package?

The required peers are `@angular/core`, `@angular/common` and `@angular/platform-browser`, which the project already has. `@angular/cdk` is required as well. A primitive that anchors a surface to a trigger uses its overlay, and `arena-tabs` uses its roving-focus key manager. The CDK supplies position only. The roles, the keys and the focus are Arena's own.

`@angular/router` and `@angular/forms` are optional peers, which no manager installs for you. Add them when you reach `@dravensoft/arena-angular/metadata` or `@dravensoft/arena-angular/forms`. `@phosphor-icons/web` is no peer. The package declares `tslib` and the same three `dependencies` as the React package (`@phosphor-icons/core`, `harfbuzzjs` and `wawoff2`), which only the `arena` command reads, at build.

Angular's own Node floor is the stricter of the two, so Angular decides which Node the project runs. Arena never refuses a Node that the framework accepts.

You do not need to run Tailwind. Every component's CSS ships compiled, and one `@import` is enough. A `--spacing` of your own moves nothing in Arena.

## What is an icon in Arena?

An icon is a glyph of Phosphor's, drawn by `ArenaIcon` (React) or `arena-icon` (Angular) as an `<svg>` that references one symbol of a sprite. Every `icon` prop in React and every `icon` input in Angular takes a Phosphor class list such as `"ph-bold ph-bell"`, and the component hands it to `ArenaIcon`. Every glyph a component draws goes through `ArenaIcon`, and so does yours.

`arena build` writes the sprite as `icons-<hash>.svg`, holding the glyphs your sources draw and the ones Arena's components draw for you. `arena build` also writes `arena.icons.generated.js` with its declaration file, exporting `ARENA_SPRITE`, the sprite's file name. Your app serves the sprite and hands its URL over once, at the root of the tree. An `ArenaIcon` with no URL warns once and paints nothing. Neither Vite nor the Angular builder serves a file of `src/` at `/` on its own, so the next section says how each one serves it.

In React, wrap the app in `ArenaIconsProvider` with the sprite's URL as `href`. The URL below is where your server serves the file:

```tsx
import { ArenaIconsProvider } from '@dravensoft/arena-react';
import { ARENA_SPRITE } from './arena.icons.generated.js';

<ArenaIconsProvider href={`/${ARENA_SPRITE}`}><App /></ArenaIconsProvider>
```

In Angular, add `provideArenaIcons(href)` to the application's providers:

```ts
import { provideArenaIcons } from '@dravensoft/arena-angular';
import { ARENA_SPRITE } from './arena.icons.generated.js';

bootstrapApplication(App, { providers: [provideArenaIcons(`/${ARENA_SPRITE}`)] });
```

A raw `<i class="ph-bold ph-bell">` paints nothing, because Arena ships no icon font; it paints only when the project installs `@phosphor-icons/web` itself and links its sheets. `arena audit` reports one as `raw-glyph`, and the `--strict` list `arena init` writes holds it. A project does not import Phosphor's own stylesheet for Arena's glyphs. [`cli.md`](./cli.md) says how the sprite is built.

## How does the toolchain serve the sprite?

`arena build` writes `icons-<hash>.svg` into `-o`, which is `src` by default. The URL handed to the provider has to reach that file.

**Vite** serves a file of `public/` at `/` under its own name, and copies it to the output unchanged. A file of `src/` imported as a URL is emitted with a name Vite hashes itself, and the import gives that name. A glob finds the one sprite whatever its hash is:

```tsx
const [sprite] = Object.values(import.meta.glob('./icons-*.svg', { query: '?url', import: 'default', eager: true }));

<ArenaIconsProvider href={sprite as string}><App /></ArenaIconsProvider>
```

A file under `assetsInlineLimit` (4096 bytes by default) is inlined into the JavaScript as a `data:` URL, instead of being emitted as a file. Set `build.assetsInlineLimit` to a function that returns `false` for `.svg` and the sprite is always a file.

**The Angular builder** copies only what its `assets` option names. Add an entry for the sprite to the build options in `angular.json`. The file then lands at the root of the output under the name `arena build` gave it, so `/${ARENA_SPRITE}` is its URL:

```json
"assets": [{ "glob": "icons-*.svg", "input": "src" }]
```

Another toolchain serves the file by its own rule. What matters is that `href` is a URL a browser can fetch.

## How do I import the stylesheets in React?

Run `arena build` first. The command writes the package sheet, the theme sheet, the icon sprite with its module, and a plugin sheet when a style plugin of yours carries CSS. Import the generated files before your own rules, in your entry file. `arena.package.generated.css` comes first and `arena.generated.css` after it. Under `--no-import` the package sheet is not written, and the sheets you import by hand take its place, before `arena.generated.css`.

```js
import './arena.package.generated.css';
import './arena.generated.css';
import './plugin.generated.css';   // only when a style plugin of yours carries CSS
```

The import happens in JavaScript. A bundler resolves each specifier as a stylesheet. `arena.generated.css` holds every colour and every font face. The package's `arena.css` has neither, so a page importing it alone paints with no colour.

## How do I import the stylesheets in Angular?

Import the generated files from `src/styles.css`. Import the generated files before your own rules. `arena.package.generated.css` comes first and `arena.generated.css` after it. Under `--no-import` the package sheet is not written, and the sheets you import by hand take its place, before `arena.generated.css`.

```css
@import './arena.package.generated.css';
@import './arena.generated.css';
@import './plugin.generated.css';   /* only when a style plugin of yours carries CSS */
```

The CDK overlay sheet comes with them: `arena.package.generated.css` imports `css/arena-cdk.css`, and so does `arena.css`.

That sheet re-bases the CDK overlay onto Arena's `--z-*` scale. Without it a dialog's menu paints behind the dialog. Write the import yourself only under `--no-import`, which writes no package sheet. Import `arena.generated.css` as well, because it alone holds the colours: `arena.css` by itself paints with no colour.

## How do I combine the sheets with Tailwind v4?

A project that compiles markup of its own with `tailwindcss` v4 keeps one entry sheet. The order is Tailwind first, then Arena's theme, then the generated sheets, then your rules. Swap `react` for `angular` in the Angular package's path.

```css
@import 'tailwindcss';
@import '@dravensoft/arena-react/css/tailwind-theme.css';
@import './arena.package.generated.css';
@import './arena.generated.css';
@import './plugin.generated.css';   /* only when a style plugin of yours carries CSS */
/* your own rules from here */
```

[`stylesheets.md`](./stylesheets.md) says what `tailwind-theme.css` holds and why a key of yours sits below it.

## Why does TypeScript report TS2307 on a stylesheet import in React?

Those import lines are a bundler idiom and not TypeScript's. A `.css` specifier resolves to no module. Under `strict` the compiler reports TS2307 on every one of them. The build then stops at the file that wires Arena in.

Most toolchains already ship the declaration, and the fix is to reference it. Vite takes `"types": ["vite/client"]` in `tsconfig.json`. A Next project generates `next-env.d.ts`.

A project whose toolchain ships none declares the modules once. Put them in a declaration file that your `include` already reaches.

```ts
declare module '*.css';
declare module '*.svg' {
  const src: string;
  export default src;
}
```

Neither declaration is Arena's to ship. An ambient `*.css` is global to whoever compiles it. A package that declared one would decide that for every project that installs it.

## How do I pass a logo to ArenaAppLogo in React?

`ArenaAppLogo` takes the mark as a node you pass. A bundled `import mark from './mark.svg'` is a specifier that TypeScript resolves no better than a stylesheet. The `*.svg` declaration above is the fix.

Passing the path as a bare string in `src` avoids the question. The price is the hashed filename that a build would have written.

## One name everywhere in React

Every export carries the `Arena` prefix, and so does every type. The component is `ArenaButton`, its props are `ArenaButtonProps`, and a tone is an `ArenaTone`.

```tsx
import { ArenaButton, ArenaCard } from '@dravensoft/arena-react';
import type { ArenaTone } from '@dravensoft/arena-react';
```

The prefix is the name and not a decoration on it. The prefix lets `"components": "auto"` tell a component of Arena's from one of yours. A `<Card>` in your source belongs to whoever wrote it. An `<ArenaCard>` belongs to Arena.

## One name everywhere in Angular

Every element carries the `arena-` prefix and every exported class carries `Arena`. The two are one name in two spellings. `<arena-button>` is the element, and `ArenaButton` is the class that goes in an `imports` array. The kebab rule turns one into the other.

```ts
import { ArenaButton, ArenaCard } from '@dravensoft/arena-angular';

@Component({ imports: [ArenaButton, ArenaCard], template: `<arena-button>Save</arena-button>` })
```

Every type carries the prefix as well, so a tone is an `ArenaTone`. The projection markers carry it already. [`exports.md`](./exports.md) lists them and says why each must be imported.

An optional value binds straight through. Every input that carries a default resolves an absent value back to it. A field of yours that may be unset needs no `?? '...'` at the call site. Write `[tone]="toast.tone"` and the default stays stated once, in the component.

## Why do class names and stylesheet names carry the component name?

A component renders `.arena-button__root`, spelt from the component's own name. A rule of yours written against that class is a rule about that component and nothing else.

Every sheet is named the same way. `css/components/arena-button.css` is the file, and `arena-button` is what you write in a `stylesheet` list. [`config.md`](./config.md) covers that list.
