# The arena command

What does `arena` write? Which flags does each command take? What does `--strict` hold, and what does an exit code mean? How do I wire it into a React or an Angular build? Read this once per project, when you wire the build.

The command ships inside both component packages, so installing Arena installs it. The command reads `arena.config.json`, your `src` tree and every style plugin directory the config declares. [`config.md`](./config.md) covers the file. [`install.md`](./install.md) covers importing what `arena build` writes.

## Which commands are there?

| command | what it does | writes | flags |
| --- | --- | --- | --- |
| `arena build` | Writes the package, theme and plugin sheets, the icon sprite and its module, and each local font cut to what the build paints, from your config and sources. | the sheets, the sprite, the cut fonts | `--config`, `--src`, `-o`, `--out`, `--no-import`, `--watch` |
| `arena check` | Names what the sheets a build would write, and your sources, get wrong: contrast, ramp, heat, weight, glyph, component and marker reports. | nothing | `--config`, `--src`, `--strict` |
| `arena audit` | Reads your sources and style plugins against the rules of the language. | nothing | `--config`, `--src`, `--strict` |
| `arena usage` | Names the components the package ships that your sources draw nowhere, and the parts your style plugins paint. A component Arena draws on your behalf counts as undrawn, because you never wrote it. | nothing | `--config`, `--src` |
| `arena init` | Copies the example config and wires the scripts below into `package.json`. | the config and `package.json`, only what is absent | `--config` |
| `arena doctor` | Says whether the project is set up: package, Node against `engines.node`, the config, and whether every sheet on disk is what a build would write. The command notes when no source imports `arena.package.generated.css`. | nothing | `--config`, `--src`, `-o`, `--out`, `--no-import`, `--strict` |
| `arena clean` | Deletes the sheets, the sprite with its module and the cut fonts `arena build` writes, by name, inside `-o`. Clean never deletes another file or the directory. | removes those files | `-o`, `--out` |

`arena --help` and `arena help` list the commands; `arena help <command>` and `arena <command> --help` print one command's flags; `arena --version` names the package and its version. `--config` defaults to `arena.config.json`. `--src` defaults to `src`, takes a file or a directory, and repeats for more trees. `-o` and `--out` are one flag and default to `src`.

## What does `arena build` write?

**`arena.package.generated.css`** is Arena's half of the stylesheet. The sheet holds the rules of every installed sheet the closed list needs, in cascade order, each sheet once, preceded by a comment naming it as `/* @dravensoft/arena-<layer>/css/<sheet> */`. The sheet holds no `@import`, so a bundler imports the one file, and a page with no CSS bundler links it as a static file. The build exits 1 and names the sheet when one the list reaches holds a `url()` that is neither inline data nor a fragment such as `url(#id)`. The build also exits 1 for an `@import` that is not a quoted relative path to a file of the installed package. The sheet's bytes move with the Arena version, the components your sources draw, the `stylesheet` keys of your config and the root style plugin, and never with palettes or fonts. `--no-import` does not write it, for a project that imports that list itself, and a copy left on disk is a file this config does not produce. A project that does not run the CLI imports `@dravensoft/arena-react/arena.css` or `@dravensoft/arena-angular/arena.css`.

**`arena.generated.css`** is your half: your palettes, your `@font-face` rules and the font-stylesheet `@import`s. The sheet imports nothing of the package, so the app imports `arena.package.generated.css` first and this file after it. Every colour comes from this file: the package declares no `--color-*`, only the rules that read them. The font roles are the half that overrides. The package declares them in the `arena-defaults` layer and your file declares them unlayered, so your file wins.

One rule holds for every root. A `--no-import` project imports the list `arena build` would have written for that config, then `arena.generated.css` last. The list is the components the sources draw and the ones Arena draws for them. The `"default"` root adds `css/style-plugin-default.css` in its slot, and a root style plugin of the project's own leaves that sheet out.

Each `<component>` stands for a sheet in the closed list `arena build` works out, for every root. That list is what `arena.package.generated.css` carries, each sheet written out in full, when a build writes it: the components the sources draw and the ones Arena draws for them. The `"default"` root adds `css/style-plugin-default.css` in its slot. Each `<family>` is a vocabulary sheet. `css/base.css` is left out when `stylesheet.preflight` is `false`. `arena.generated.css` goes in a stylesheet of its own, imported after the list, so the package's sheets and yours never share a file.

**`arena.runtime.generated.json`** is written when the config sets `"runtimePalettes": true`. The file holds the level list, the washes and the style plugin's roles for each polarity, which `arenaRuntimePalette`, `arenaCheckPalette` and `arenaPaletteDeclarations` read as their `data`. [`theme.md`](./theme.md) covers them.

**`icons-<hash>.svg`** is the Phosphor sprite: one `<symbol>` per glyph your sources draw and every glyph Arena's components draw for you, each cut from `@phosphor-icons/core`, the official 256-unit SVGs. Your sources are read as text; Arena's half is the package's `icons.json`, computed from its renders. A glyph named in a file that draws a navigation item also reaches the filled weight, since an active item draws filled. When an item takes its `icon` from an expression, every glyph your sources name reaches the filled weight, which can carry symbols the view never asks for. The name carries a hash of the file's bytes, so it changes exactly when the sprite does, and a sprite from an earlier build is removed. A glyph Phosphor does not draw at that weight is a `glyph` report and gets no symbol. A glyph your sources name that no literal in an `ArenaIcon`, `arena-icon` or `icon` attribute names still reaches the sprite and is a `glyph` report. That report stays off once any source hands one of those an expression. A project that passes icons as values gets no such report, and a glyph it names and never draws costs sprite bytes silently. A glyph drawn through a class of its own is reported by the audit's `raw-glyph` rule.

**`arena.icons.generated.js`** and its declaration file in React, or **`arena.icons.generated.ts`** in Angular, export `ARENA_SPRITE`, the sprite's file name, under a fixed name. The Angular import keeps the `.js` specifier: TypeScript resolves it to the `.ts` and `ngc` emits the `.js`. A layer removes the names it does not write, so a `.js` left beside the Angular `.ts` is deleted. The app serves the sprite and hands its URL over once, to `ArenaIconsProvider` in React or `provideArenaIcons(href)` in Angular. [`install.md`](./install.md) shows both.

**`<stem>-<hash>.woff2`** is each font whose `src` in `arena.config.json` is a file on disk, cut to Latin-1 and the weights your sheets paint. `<stem>` is the source file's name without its extension, so `fonts/archivo.woff2` becomes `archivo-<hash>.woff2`. The `@font-face` rule in `arena.generated.css` names the cut file and carries a `unicode-range`, so a browser fetches it only for text in that range. A variable face keeps its weight axis cut to the range painted, and a static face keeps the weights painted. The name carries a hash of the file's bytes, and a cut from an earlier build is removed. A `src` that is a stylesheet URL or a remote file is left as written, with a `font` report. A weight the build paints that the cut lost is a `weight` report. The packages carry `fonts/` with Archivo, Familjen Grotesk and Spline Sans Mono, each beside its OFL text. The example config names them by local path, and `arena init` copies them beside the config.

**`plugin.generated.css`** is written when a style plugin carries a `plugin.css`. The sheet holds that CSS in the reserved cascade layer and leads with the layer order itself, so where a bundler places it cannot change what wins.

A sheet is written only when its bytes change, so a bundler watching an untouched sheet does not rebuild. A sheet this config does not produce is removed. A build prints how many reports it saw and exits 0 on them; `arena check` names them. Keep every generated file out of version control: the sheets, the sprite with its module and the cut fonts.

**`--watch`** builds once, then rebuilds after each burst of changes to the config, a source under `--src` or a style plugin directory. A path that is not there yet is awaited. A build that cannot run prints why, and the next change builds again. Ctrl-C stops the watch and exits 0. The watch never reacts to the sheets it writes, or to anything under `node_modules`, `dist`, `.git`, `.angular` or `coverage`. Name your source trees with `--src`: a `--src .` holding another build directory rebuilds on its churn.

## What does `--strict` hold?

A report never changes the exit until `--strict` holds it. Bare, `--strict` holds every kind that command reports; `--strict=contrast,glyph` holds the kinds you name. A kind with rules can also be held one rule at a time, as `<kind>:<rule>`. `--strict=audit:emoji,restated` holds the `emoji` rule of `audit` and every `restated` report, and only reports the other audit rules. A kind another command holds, a rule its kind does not have, a rule on a kind without rules, or a `--strict=` naming none, is refused.

| command | kinds |
| --- | --- |
| `arena check --strict` | `components`, `contrast`, `ramp`, `weight`, `font`, `glyph`, `markers`, `heat` |
| `arena audit --strict` | `audit`, `restated` |
| `arena doctor --strict` | `environment` |

| kind | rules `--strict=<kind>:<rule>` names |
| --- | --- |
| `audit` | one per tag, tabled with the rule each reports in [the next section](#what-does-each-audit-tag-report) |

**`arena init` writes the names that exist when it runs.** The `arena:audit` script it writes names every audit rule and `restated`. A rule a later package adds is reported there, and changes no exit until you add its name. A bare `--strict`, or `--strict=audit`, holds every rule, later ones included. An audit finding ends in its rule, such as `(raw-value)`. A `stale-allowance` finding ends in no tag: it names an `arena-audit allow` marker on a line with nothing to exempt, and `--strict=audit:stale-allowance` holds it.

`unknown-input` names a static attribute on an Arena element in an Angular template that the component takes as no input or output. A forms attribute such as `formControlName` is never named. When a directive of your own reads the attribute, mark the line `arena-audit allow`.

`unknown-property` names a `var()` in a style plugin file that reads no role, token, alias, channel, palette colour or property your sources declare. A read such as `var(--arena-nothing, transparent)` takes its fallback in silence. The message gives the nearest listed name when one is close. `unknown-part` names a `[data-arena-part]` in a style plugin file that no component declares, so the rule reaches nothing. When the name is a part with a state written onto it, such as `menu.item-destructive`, the message gives the part and the `data-arena-*` hook that marks that state. Neither rule reads a file outside a style plugin directory, and neither reads when the package carries no list of channels or of parts. Mark a line `arena-audit allow` to silence either.

`contrast` also reports a chart axis answered with no more contrast than the grid (`--edge-axis` against `--edge-separator` on base-100). `contrast` reports a status hue whose `--hue-<hue>-on-ink` measures under 4.5:1 over `--hue-<hue>-ink`, the label of a solid badge over its fill, in either polarity.

`contrast` reports a palette whose `base-100` sits on the other side of its declared polarity. A dark palette wants an OKLab lightness under 0.5 and a light one wants 0.5 or more. The message reads `polarity, base-100 #fafafa reads as light, and the palette declares dark`, for a declared palette and for a runtime one alike.

**Name the kinds when one of them is a decision you already made.** A brand under 4.5:1 can be deliberate, and one switch would make it the price of holding the rest in CI. `weight` says a role asks for a weight the face you loaded does not carry. `font` says a font was not cut because its `src` is not a file on disk or is not one of the formats the cut reads (woff2, ttf and otf). `glyph` is a name Phosphor does not draw, or a glyph no literal in your sources draws through `ArenaIcon`, `arena-icon`, an `icon` attribute or a `#ph-` symbol reference. The second report stays off once any source hands an icon member an expression. `markers` is an Angular projection marker, such as `[footer]`, written in a template that does not import its directive. That marker renders nothing, and neither the build nor `ngc --strictTemplates` reports it; [`exports.md`](./exports.md) lists every marker. `heat` says two neighbouring heat steps Arena derives sit under 0.06 of lightness apart, or the five are out of order, so a reader cannot tell them apart. A palette that pins `heat-1` to `heat-5` is read for order alone. `heat` names a step no further from the surface than the one before, because the heatmap reads the steps by magnitude. Raise the ink contrast on `base-200`, or fix the pinned steps. `arena init` leaves `heat` out of `arena:check`, so name it there to hold it. `restated` is a plugin rule restating the value its part's slot already paints. `environment` says Arena's own icons went uncounted, outside an Arena package or without its `icons.json`. In `arena doctor` it also says Node misses `engines.node`, or that range is one it cannot compare. `wash` is reported and never held: a token on a wash of its own colour clears AA at no percentage, and a gate nobody can fix is not a gate.

## What does an exit code mean?

| code | meaning |
| --- | --- |
| `0` | The command did its job. Reports may print. |
| `1` | A project problem: a config that parses and is invalid, a `stylesheet` name the package does not ship, an unanswered root role, or a report `--strict` holds. `arena doctor` exits 1 on anything that stops a build, and on a sheet that is missing, stale or no longer produced. |
| `2` | The command cannot run: an unknown, refused or repeated flag, a config it cannot read as JSON, or a missing `--src`. A missing `@phosphor-icons/core`, `harfbuzzjs` or `wawoff2` is a 2, as is a file it cannot write or delete, or `arena init` with no `package.json`. |

## What does each audit tag report?

The middle column is the rule of [the rules section of `SKILL.md`](../SKILL.md) that the tag reports.

| tag | the rule it reports | what fires it |
| --- | --- | --- |
| `compat-alias` | none of the language rules | A stylesheet in a style plugin directory reads one of Arena's compatibility aliases through `var()`, which names a step of the ramp instead of a role. |
| `danger-fill` | Danger is outline, never filled. | A background declaration outside a style plugin directory reads a danger token not mixed with transparent, which fills a surface where Arena draws danger as an outline. |
| `emoji` | No emoji, in product or in copy. | A line of a source holds an emoji character. |
| `icon-element` | Icons are Phosphor class-name strings, drawn by Arena's components or by ArenaIcon; a raw ph-* element paints nothing. | An `icon` or `iconRight` attribute is given an element in braces, where Arena takes a Phosphor class-name string. |
| `one-primary` | One primary accent per view. | A second action in one view, or in one modal, takes the primary emphasis by class or by leaving a primary-default component without one. |
| `outline-gap` | none of the language rules | A source draws Arena headings at two levels with a level missing between them, such as an h1 and an h3 with no h2. |
| `own-class` | Only a class of the vocabulary goes on an Arena component. | A component carries a class outside its vocabulary or a computed one, or a stylesheet targets an `arena-` class anywhere or a `data-arena-part` hook outside a style plugin. |
| `raw-glyph` | Icons are Phosphor class-name strings, drawn by Arena's components or by ArenaIcon; a raw ph-* element paints nothing. | An element other than `ArenaIcon` holds a Phosphor glyph class, or binds its class to a non-literal value in a file naming one; Arena ships no icon font. |
| `raw-value` | Tokens are the only styling layer. No gradients, on any surface. | A style holds a hex, colour or bare pixel length, or a gradient outside a style plugin unless `gradientMark` is set, or a class holds a non-token bracket value. |
| `router-link` | Never wrap an Arena component in your router's own link. | A link of your own, such as `a`, `Link` or `routerLink`, directly wraps an Arena card, side nav item, bottom nav item or table cell. |
| `stale-allowance` | none of the language rules | An `arena-audit allow` marker sits on a line with nothing to exempt. |
| `unknown-input` | none of the language rules | A static attribute on an `arena-` element in an Angular template names no input or output of that component. |
| `unknown-part` | none of the language rules | A style plugin rule names a `data-arena-part` no component declares. |
| `unknown-property` | none of the language rules | A style plugin rule reads a `var()` that names no role, token, alias, channel, palette colour or property your sources declare. |
| `wrapped-link` | none of the language rules | A link of your own, such as `a`, `Link` or `routerLink`, directly wraps an Arena link, which is already an anchor. |

## What does the audit read?

The rules it reports, and the ones nothing reads, are the router's: [the rules section of `SKILL.md`](../SKILL.md). The audit reads TypeScript, stylesheets and, in Angular, templates. **Every rule is read in a scope.** Inside a directory `stylePlugins` declares, a part hook is what you are meant to select and a gradient is yours to paint, so neither is reported there. A compiled `arena-` class and a raw value are reported in both scopes. A comment is prose and declares nothing. Exempt a line the audit is wrong about with an `arena-audit allow` comment on that line; the audit reports the allowance once nothing on the line needs it. Nothing else checks your sources against the rules. With no `arena.config.json`, audit and usage read no style plugin; a named `--config` that is not there exits 2.

## How do I wire it into a React build?

Run `arena init` once. In a project on `@dravensoft/arena-react` it adds these scripts, and the config when it is absent:

<!-- @shared scriptsReact GENERATED by bun run generate:npm-pages. Edit that script, not this copy. -->

```json
{
  "scripts": {
    "prebuild": "arena build",
    "predev": "arena build",
    "arena:check": "arena check --strict=components,glyph,markers",
    "arena:audit": "arena audit --strict=audit:compat-alias,audit:danger-fill,audit:emoji,audit:icon-element,audit:one-primary,audit:outline-gap,audit:own-class,audit:raw-glyph,audit:raw-value,audit:router-link,audit:stale-allowance,audit:unknown-input,audit:unknown-part,audit:unknown-property,audit:wrapped-link,restated"
  }
}
```

<!-- @shared scriptsReact end -->

A `--config` other than the default is carried into every script it writes. `arena:check` holds the kinds a project decides nothing about and leaves `contrast` and `ramp` to the brand's owner. Run both in the job that runs your tests.

## What if a script is already there?

`arena init` never overwrites. A script already reading what it would write is left alone; another `arena:check` or `arena:audit` is kept and named. A `prebuild`, `predev` or `prestart` that does not run `arena build` is left too. Init prints the line to write instead, `make it: arena build && <yours>` with the same `--config`, and exits 0.

A `pre` script runs only where the package manager runs one. npm 11.19, pnpm 11.22 under its default configuration and bun 1.4 were each observed running a project's `prebuild` ahead of its `build`. Under a manager not observed here, write the command into the script itself, as `"build": "arena build && vite build"`.

## How do I run it once?

From the project:

```bash
npx --no-install arena doctor     # or: pnpm exec arena doctor
```

The registry holds a different package named `arena`, so a runner that may download one is told not to. [`stack.md`](./stack.md) says which runners reach the command, with the evidence for each.
